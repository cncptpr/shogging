# CalDAV review (shogg)

The following was generated by AI, when asked to analyse the shogg library for correctness and additional features regarding CalDAV.

## Correctness vs CalDAV/WebDAV

- Discovery uses `/.well-known/caldav` and expects redirect; common, but some servers return 200 with DAV headers, which would currently be treated as error.
- `current-user-principal` and `calendar-home-set` PROPFINDs are structurally correct, but `Depth: 1` for `current-user-principal` is broader than needed and can return multiple responses; the parser always uses the first response without checking `propstat` status.
- Calendar discovery PROPFIND is aligned with `DAV:resourcetype`, `CALDAV:supported-calendar-component-set`, and `displayname`, but the decoder requires `getctag`, `displayname`, and `supported-calendar-component-set` to be present. The spec allows these to be absent; if missing, calendars should still be returned, and supported components should default to “all”. Current logic drops such calendars.
- `cs:getctag` is an Apple extension (not RFC 4791). Using it is fine for ctag-based sync, but it is not standard and should be optional/fallback.
- `calendar-query` REPORT for VTODO is correct at a high level (REPORT + filter), but the iCalendar parser is not RFC 5545 compliant: no line folding, no parameter parsing (`SUMMARY;LANGUAGE=…`), no timezone handling, and it fails if a `VTIMEZONE` appears before `VTODO` (which is common). This causes false errors on valid calendar data.
- Task serialization omits line folding and only escapes a small subset of characters; it does not enforce REQUIRED properties beyond a minimal set. This can produce non-compliant or interop-fragile VTODO payloads.
- ETag usage for update/delete is correct (If-Match), but response handling assumes ETag header is present for successful PUT; some servers omit it.

## Existing TODOs / likely next implementations

- Finish iCalendar parsing/serialization (folding, parameters, VTIMEZONE, arbitrary ordering, more fields).
- Fix calendar color handling and remove the hard-coded Apple namespace assumption when absent.
- Improve error mapping (currently several places TODO or overly strict `propstat` status handling).
- Add RFC 6578 `sync-collection` support (already noted in `docs/syncing.md`).
- Update `LAST-MODIFIED` on task updates (currently TODO).

## Short list: other CalDAV features worth adding

- `calendar-multiget` and `free-busy-query` REPORTs (RFC 4791).
- Time-range and text filters in `calendar-query` (RFC 4791) for efficient event/task sync.
- MKCALENDAR support for creating calendars and setting properties (RFC 4791).
- DAV:sync-token + `sync-collection` support (RFC 6578) for efficient incremental sync.
- Access control/privilege discovery (WebDAV ACL, RFC 3744) and `supported-report-set` introspection.
